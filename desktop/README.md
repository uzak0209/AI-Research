## 起動

入口はリポジトリ直下の `just desktop`。Cursor 経由だと `ELECTRON_RUN_AS_NODE=1` が付いて Electron が Node になるので、`npm run dev` / `just desktop` はそれを外す。API の既定は prod（`https://ai-research.streeeak.link`）。ローカル wrangler に向けるときは `just desktop-cloud`。

```bash
just desktop
just seed-desktop    # 空の DB を機能紹介用のデモで埋める。起動し直す
```

作業フォルダの作成・開くは macOS なら **ファイル** メニュー。クラウドは **アカウント → Google でログイン**。書誌の補完はログイン後に Worker の BFF 経由。

左にラベル付きナビ＋絞り込み、その右が作業領域、下にステータスバー。

| OS | ウィンドウ枠 |
|---|---|
| macOS | 信号機は左上（`hiddenInset`）。**ファイル → フォルダを作る / フォルダを開く**は画面最上段のメニューバー |
| Windows | キャプションボタンは右（`titleBarOverlay`） |
| Linux | OS の枠のまま |

| 画面 | 中身 |
|---|---|
| ライブラリ | 左ナビで絞り込み、中央が一覧、右が詳細。検索・タグ・メモ・添付 |
| 新着候補 | 関連度順の一覧と詳細。ライブラリへ保存できる |

## UI の基準

## PDF での取り込み

ツールバーの **PDF**（PDF から取り込む）で複数まとめて選べる。1 ファイル = 1 文献。

書誌は**ローカルだけで**この順に埋める。

1. PDF の Info 辞書（Title / Author / CreationDate）
2. 1〜2 ページ目の本文から DOI（`10.xxxx/...`）
3. Title が無ければ本文の先頭 12 行から表題らしい行を推測

**取れなかったものは空のままにする。**推測で埋めた項目は取り込み結果に
「タイトルは推測」と出るので、後から直せる（`C-07`）。

**PDF は元の場所に置いたまま**で、コピーも移動もしない。パスだけを覚える（`C-08`）。
添付を「外す」してもファイルは消えない。

### 書誌の補完（決定と実装）

**決定**（ADR-0002 / 0003）: `references/` に公開文献を置くとライブラリに入り、BFF が Orca 安価モデルで書誌を構造化する。原稿・ノートは送らない。Typst は Hayagriva `.yml`、TeX は `.bib` へマーカー内書き出し（FR-12）。処理は `desktop/src/bibliography/`（domain / application / infrastructure）。

**いま動くもの**: `references/` 追従と PDF 取り込みはローカル抽出のあと Worker の `POST /bff/bibliography`（Orca 構造化出力）で書誌を補い、OA の直 PDF URL だけ `references/` に置く。Typst は Hayagriva `.yml`、TeX は `.bib` へマーカー内書き出し（ファイルが無ければ作らない）。Electron から OpenAlex / Orca は叩かない。

Google Cloud Console で OAuth クライアント（種別 **Desktop**）を作り、ループバック `http://127.0.0.1` を使う（ポートは問わない）。
client は Worker の Secret。アプリは **アカウント → Google でログイン**。
OAuth App が無い間は `just desktop-cloud` でローカル access を載せても書誌は叩ける。

### 文献を選んだときの表示

**PDF があれば、まずビューアが開く。**書誌情報とメモは右上の「書誌情報とメモ」で開き、
そこから「← PDF を読む」で戻る。PDF が無い文献は書誌情報が開く。

PDF を 1 件だけ取り込んだときは、結果一覧を挟まずそのままビューアに入る。

### 書き込み

ビューア上部で道具を切り替える。

| 道具 | できること |
|---|---|
| 選択 | 文字を選ぶとハイライトが付く |
| ペン | 自由に線を引く。太さは細・中・太 |

どちらも色は 4 色（黄・緑・赤・青）。

### コメント（Word / Google ドキュメント方式）

文字を選ぶと**その場に小窓**が出る。

- 色を押す → ハイライトだけ付ける
- 「コメントを追加」を押す → ハイライトを付けて、**右の余白に付箋**を作り入力に移る

付箋は**元の箇所と同じ高さ**に並ぶ。重なるときは下へずらす。
本文のハイライトを押すと対応する付箋へ、付箋の「本文へ」で元の箇所へ移る。
コメントが無いハイライトを押すと「コメントを追加」「削除」の小窓が出る。

入力をやめて 0.6 秒で自動保存し、保存できたかを時刻つきで表示する。
保存に失敗したときは「保存した」と出さない（`C-07`）。

### マーカーの濃さ

`Range.getClientRects()` は**文字の断片ごと**に矩形を返す。pdf.js の文字層は 1 行が
複数の span に分かれているため、隣り合う矩形がわずかに重なる。
そのまま 1 つずつ半透明で塗ると、**重なった所だけ色が濃くなって縞になる**。

[rects.ts](src/renderer/rects.ts) で**行ごとにひとつながりへまとめてから**塗る。
保存時と描画時の両方でまとめるので、**以前に保存した書き込みも直る**。

濃さは `opacity: 0.28`（重ね掛かりが無い前提の値）。
コメントが付いたものは枠で囲わず下線で示す。囲うと文字が読みにくいため。

### 倍率

**既定は「幅に合わせる」。** 表示領域の幅からページの倍率を計算する。
固定倍率にすると、狭いペインではページが溢れて左側が画面外に出て読めなくなる。
拡大・縮小すると固定倍率に切り替わり、「幅に合わせる」で戻せる。

PDF を読んでいる間は一覧を細くして本文に幅を回す。

**PDF 本体には一切書き戻さない。**座標・引用文・コメントをローカル DB に持つだけなので、
他のツールで同じ PDF を開いても元のままになる（`C-08`）。
座標はページ幅・高さに対する比で持つので、拡大率を変えても位置がずれない。

おかしな座標（比ではなくピクセル値）は保存時に弾く。
静かに描画がずれるより落とす方がよいため。

## 実測で決めたこと

### SQLite は `node:sqlite`（ネイティブ npm 依存ゼロ）

Electron 44 は Node 24.21 を積んでおり、`node:sqlite` に `enableLoadExtension` がある。
**better-sqlite3 を入れない。** OS ごとの prebuild もリビルドも要らない（`NFR-05`）。

### sqlite-vec は Electron で読める

ER 図で未決だった点。実機で `vec_version()` = v0.1.9、KNN も正しく動いた。
読めない環境では**黙って縮退せず**起動時に落とす（`C-07`）。

### 採点は `utilityProcess`

1 件 80 ms のため、レンダラでもメインでも回さない（`NFR-06`）。
**1 件ごとに DB へ確定**するので、途中で閉じても済んだ分は残り、
残りは `scored_at IS NULL` で拾って再開する（採点キュー表は作らない）。

## スキーマが ER 図と違う点

実際に動かして判明した制約による。

| ER 図 | 実装 | 理由 |
|---|---|---|
| `references` | `reference_items` | `references` は SQLite の予約語で CREATE TABLE できない |
| `nearest_claim_id`（text） | `nearest_chunk_id`（integer） | 主張は `chunks` なので型と参照先を合わせた |

## 表示の原則（C-07）

- **有効／除外を断定しない。** 順位だけを出す
- **未採点は「未採点 n 件」と実数で出す。** 推定や「およそ」を書かない
- **未採点を一覧に混ぜない。** 混ぜると採点漏れに気づけない
- **採点前の順位を先出ししない**（楽観的 UI を採らない）
- 概要や手法を変えたら採点済みの印を落とす。古い順位を見せ続けない

## つまずいた点（同じ踏み方をしないため）

- **`rollupOptions.external` を自分で書くと `externalizeDepsPlugin` の設定を上書きする。**
  `dependencies` が丸ごとバンドルされ、`pdfjs-dist` が
  `Setting up fake worker failed: Cannot find module '.../pdf.worker.mjs'` で落ちた。
  外部化する対象は `electron` ＋ `package.json` の `dependencies` を自分で並べる
- **外部化はサブパスにも効かせる。** `pdfjs-dist` と書いても
  `pdfjs-dist/legacy/build/pdf.mjs` は一致せずバンドルされる。`^名前($|/)` の正規表現で外す
- **`electron` は devDependency なので `externalizeDepsPlugin` の対象外。**
  明示的に external に入れないと npm パッケージ側（バイナリのパスを返すだけ）が
  同梱され、`Electron failed to install correctly` で落ちる
- **日本語 PDF は文字断片の間に空白を入れない。** pdf.js は 1 行を複数の断片で返すため、
  無条件に空白を挟むと「麻 雀 A I の 開 発」のように割れる。CJK の境目では挟まない
- **一覧の再描画で詳細ペインを触らない。** ハイライトを付けると
  「書き込みが増えた → 一覧を更新 → 詳細ペインを描き直す」の流れで
  **PDF ビューアの DOM ごと作り直され、ビューアが消えた**。
  一覧の更新は一覧だけにとどめ、選択が消えたときだけ詳細を空にする
- **閉じた後の非同期処理で描き続けない。** ページ描画は await を挟むので、
  途中で閉じられることがある。`container.isConnected` を見て打ち切る
- **半透明の矩形を重ねて塗らない。** `getClientRects()` は文字の断片ごとに矩形を返し、
  端が重なる。1 つずつ塗ると重なった所だけ濃くなる。行ごとにまとめてから塗る
- **溢れる可能性のある要素に `align-items: center` を使わない。**
  中央寄せしたページが枠より広いと**左側が画面外に出て触れなくなる**
  （実際に「右半分しか見えない」状態になった）。`margin-inline: auto` なら溢れても左端が残る。
  あわせて親に `min-width: 0` を付けないと、ページの実寸で枠ごと押し広げられる
- **Windows の GUI プロセスは stdout が端末に出ない。**
  起動時の失敗は `userData/startup.log` に残している
- `schema.sql` はバンドルに含まれないので `?raw` で文字列として取り込む

## 未対応

- コメントの付箋は画面幅 900px 未満で隠れる（本文を読めることを優先）
- 画像だけの PDF（文字が取れない）。`textEmpty` で検知はするが OCR はしない。
  ペンでの書き込みはできる
- 消しゴム（線の一部を消す）。いまは線ごと削除のみ
- クラウド同期、引用ファイル書き出し、CLI
- 配布（electron-builder 等）と署名
- 日本語の要旨・プロフィールでの採点精度（未計測）
