# 要件

何を・なぜ。手段は [ADR 3 本](adr/)。

## 問題・ユーザー

手作業: トレンド調査 / 重複確認 / 有用論文の発見 / **次のテーマ候補** / 参考文献の整理。

- 論文を書く研究者。未公開データ・原稿を手元に持つ
- 分野非依存。配布する（`C-02`）
- **特定の参考文献マネージャ（Zotero 等）への依存は前提にしない**

## 成功条件（初版）

1. アプリ未起動でも日次で新着候補が溜まる
2. 起動すると重複・活用可能性の報告が読める
3. **アプリ内で参考文献を管理できる**（ライブラリ・コレクション相当）
4. 執筆中原稿の主張を検査できる
5. 外部 LLM を統制下で呼べる（**利用自体が目的**。ゲートウェイは ADR-0002）
6. 新着から次のテーマ候補を提示できる
7. **GUI と同じローカルデータに CLI から触れられる**

やらない: 全分野完全網羅 / クラウド完結の研究環境 / 外部 LLM ゼロを既定 /
**初版で特定マネージャの必須連携** / CLI だけで GUI を置き換えること

### FR-05 / FR-11 の受け入れ（要約）

- 書誌（タイトル・著者・年・DOI 等）をローカルに保持・検索できる
- コレクション／タグ相当で整理できる
- 日次レポートや判定結果から「ライブラリに入れる」ができる
- CLI は GUI と**同じライブラリ**を読む／書く（二重管理しない）
- Electron 未起動でも CLI だけでライブラリ操作できる
- 他ツール連携（BibTeX 書き出し等）は初版必須ではない → 未決／候補
