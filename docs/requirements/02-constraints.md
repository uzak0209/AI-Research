# 制約

ゴールの成功条件とは別に、破ってはいけない条件。

| ID | 要約 | ADR |
|---|---|---|
| C-01 | 未公開データの恒久外部インデックス禁止 | 0003, 0004, 0012 |
| C-02 | 配布前提 | 0008, 0009 |
| C-03 | 未公開データを扱う機能は無効化できる | 0010 |
| C-04 | 未公開データを外部推論に出すときは統制する | 0010, 0013 |
| C-05 | 分野固有知識を製品コアに埋め込まない | 0009, 0012 |
| C-06 | 開発者の有料 API キーをクライアントに置かない | 0008 |
| C-07 | 欠損を成功と偽らない | 0011 |

## C-01

未公開研究データの**恒久的な検索用インデックスを外部に作らない**。
クラウドに置いてよいのは公開可能な概要・キーワード・論文識別子など。
埋め込みの網羅送信と、都度のプロンプトは別物（後者は `C-04`）。

## C-02

他人にも配布する。他人の研究データ・利用量・課金を預かる前提。

## C-03

未公開データを外部 LLM に送れない利用者向けに、該当機能を完全オフにでき、他機能は残る。

## C-04

未公開データを外部推論に出すとき: 分類が機能ごとに決まっている、転送先が予測不能に変わらない、送る範囲が分かる同意、虚偽の説明禁止。

## C-05

特定分野の会議・ソース・モデルをコアにハードコードしない。

## C-06

開発者負担の課金キー（LLM ゲートウェイ等）を配布アプリに埋め込まない。
利用者本人の Zotero キー等は別。

## C-07

自動処理の欠落を「結果ゼロ」と同じ見た目にしない（`FR-08`）。
