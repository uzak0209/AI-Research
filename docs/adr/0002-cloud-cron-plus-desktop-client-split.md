# ADR-0002: 定期実行はクラウド、対話処理はデスクトップに分離する

- **ステータス**: 承認済み
- **日付**: 2026-09-19

## コンテキスト

要件は次の2点を同時に満たす必要がある。

1. **1日1回、自動で最新論文を収集・解析する**
2. **ユーザーは常にアプリを起動していない**

ローカルの cron / launchd に載せる案も検討したが、Mac がスリープしている、電源が入っていない、アプリが起動していない、といった状況で実行が落ちる。`launchd` の `StartCalendarInterval` はスリープ復帰後に遅延実行してくれるが、複数日スキップされた場合の挙動が読みにくく、「毎日の履歴が揃う」保証が弱い。

一方で、要件に挙がっている D1 (Cloudflare D1) はクラウド上の SQLite であり、これに書き込む主体はクラウド側に存在しなければ意味がない。

## 決定

処理を2層に分離する。

**クラウド層 — Cloudflare Workers + Cron Triggers + D1**

- 1日1回の Cron Trigger で起動
- 論文ソース API から新着論文のメタデータを取得
- 後述の「研究プロフィール」による粗い関連度スコアリング
- 結果を日次レポートとして D1 に蓄積
- ユーザーの起動状態に一切依存しない

**デスクトップ層 — Electron アプリ**

- 起動時に D1 から未取得のレポートを一括で取り込む（プル型の同期）
- ローカル RAG による精密な重複判定・関連性判定
- Zotero への保存
- 原稿のファクトチェック実行
- 手動実行のトリガー

デスクトップは「常時稼働を前提としないクライアント」であり、クラウドが「常時稼働する記録装置」である。同期はデスクトップ起動時のプル型とし、クラウドからのプッシュは行わない。

## 検討した代替案

**ローカル launchd のみ** — 起動状態に依存するため要件を満たさない。却下。

**クラウドのみ（Web アプリ）** — 後述 ADR-0004 の通り、未公開の研究データをローカルに留める方針と両立しない。却下。

**デスクトップからのプッシュ購読（WebSocket 常時接続）** — アプリが起動していない時間帯のイベントをどう扱うかの複雑さが増すだけで、プル型に対する利点がない。却下。

## 帰結

**良い点**

- アプリを閉じていても日次レポートが溜まる
- クラウド側は API 取得とスコアリングのみで、状態を持たないため障害時の復旧が容易
- D1 が履歴の単一の真実になるため、デスクトップを再インストールしても過去のレポートを復元できる

**悪い点**

- クラウドとデスクトップで2つのデプロイ対象を維持する必要がある
- 同期の冪等性を自前で担保する必要がある（レポートに一意 ID を振り、デスクトップ側で取り込み済みカーソルを管理する）
- クラウド側は完全な関連度判定ができない。これは ADR-0004 の二段フィルタで対処する

## 未決事項

- Cron の実行時刻（ユーザーのタイムゾーンと、各論文ソースの更新タイミングを踏まえて決める）
- D1 上のレポート保持期間と、古いレポートのアーカイブ方針
