# ADR-0002: 定期実行はクラウド、対話処理はデスクトップに分離する

- **ステータス**: 承認済み
- **日付**: 2026-09-19

## コンテキスト

ゴール成功条件 1: **アプリを起動していなくても、日次で新着論文の候補が溜まる**（`FR-01`, `NFR-01`）。

同時に、精密な重複判定・ファクトチェック・Zotero 保存・手元 RAG は
未公開データを扱うためデスクトップ側が自然である（成功条件 2〜4、`C-01`）。

ローカル cron / launchd だけでは、スリープ・電源オフ・アプリ未起動で日次保証が弱い。

## 決定

処理を2層に分離する。

**クラウド層 — Cloudflare Workers + Cron Triggers + D1**

- 1日1回の Cron で論文ソースから新着メタデータを取得
- 研究プロフィールによる粗い関連度スコアリング（ADR-0004）
- 日次レポートを D1 に蓄積（起動状態に非依存）
- 公開データのみ。未公開原稿・実験データは置かない

**デスクトップ層 — Electron アプリ**

- 起動時に D1 から未取得レポートをプル
- ローカル RAG による精密な重複・活用判定（成功条件 2）
- テーマ候補の精密側・表示（成功条件 6、ADR-0016）
- Zotero 保存（成功条件 3）
- 原稿ファクトチェック（成功条件 4）
- 手動実行のトリガー

同期はプル型。クラウドからのプッシュは行わない。

## 検討した代替案

**ローカル launchd のみ** — 成功条件 1 を満たさない。却下。

**クラウドのみ（Web アプリ）** — 未公開データをクラウドに載せる前提になり `C-01` と衝突。却下。

**デスクトップからの常時 WebSocket** — 起動していない時間の扱いが複雑で利点が薄い。却下。

## 帰結

**良い点**

- 成功条件 1 と、未公開データを扱う成功条件 2〜4 を両立できる
- D1 が履歴の単一の真実になる

**悪い点**

- デプロイ対象が二つ
- 同期の冪等性が必要
- クラウド単独では精密判定できない → ADR-0004

## 未決事項

- Cron の実行時刻、D1 のレポート保持期間
