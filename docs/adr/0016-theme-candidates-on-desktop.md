# ADR-0016: テーマ候補は日次候補集合の上で、デスクトップ側 LLM が生成する

- **ステータス**: 承認済み
- **日付**: 2026-09-19

## コンテキスト

ゴール成功条件 6 / `FR-09`: 新着から次に追うテーマ候補を提示できる。
問題定義にも「最新の研究から次のテーマ候補を見つけてくる」がある。

候補の入力は ADR-0004 の二段フィルタで既に存在する。
テーマ生成をどこで・どのデータ分類で行うかを決める必要がある。

## 決定

**テーマ候補の生成はデスクトップ起動後に行う。** クラウド cron では「候補論文の集合」までとし、テーマ文の生成はしない。

### パイプライン

1. 日次レポート（粗い候補）を D1 からプル（ADR-0002）
2. ローカルで精密フィルタ後の論文集合を得る（ADR-0004 第二段）
3. 公開メタデータ（タイトル・要約・識別子）と、利用者が許した研究プロフィール（C2）をプロンプトに載せ、外部 LLM でテーマ候補を生成（ADR-0007, `interactive` キー）
4. 未公開原稿・実験ノート本文は既定では載せない。載せる場合は C3 と同意（ADR-0010）
5. 結果はプロジェクト単位でローカル保存し、UI に提示（詳細 UI は `OQ-05`）

### データ分類

| 入力 | 分類 |
|---|---|
| 公開論文メタデータのみ | C1 |
| ＋研究プロフィール | C2 |
| ＋未公開原稿・メモ | C3（オプトイン） |

既定は **C2 まで**。C3 を使う設定は `C-03` で無効化できることと両立させる。

### モデル

C2: 許可リスト内。C3 オプトイン時は単一モデル固定・フォールバック無効（ADR-0010）。

## 検討した代替案

**クラウド cron でテーマ文まで生成** — 起動不要で届くが、プロフィール以外の文脈が使えず、個人化が弱い。レポート肥大化。初期はデスクトップ生成とする。

**ローカル LLM のみ** — 安全だが品質・配布コスト。将来選択肢（ADR-0010 と同趣旨）。

**精密フィルタ前の全候補で生成** — ノイズが多い。第二段後に限定。

## 帰結

**良い点**: 成功条件 6 を二段フィルタと LLM 目的（成功条件 5）の延長で実現。未公開を既定で載せない。

**悪い点**: アプリを開くまでテーマが更新されない。UI・フィードバックは `OQ-05` 待ち。
