# ADR-0003: 参考文献ライブラリと原稿ファクトチェック

- **ステータス**: 承認済み / **日付**: 2026-09-20（改訂: PDF 閲覧・注釈を決定／改訂 2026-09-21: `references/` 追従をライブラリ追加とみなす。書誌は ADR-0002 の Orca／同日: OA 直リンクの PDF だけ自動取得／**同日再改訂: 採点用に候補 PDF も `candidates/` へ取得可**／**改訂 2026-09-22: `mypaper/` に置いた自分の PDF も書誌を作る。原稿は出さない**／**同日: OA 直 PDF を収集時に取り、arXiv を優先する**）
- **要件**: FR-04, FR-05, FR-07, FR-11, FR-12, FR-14, C-01, C-03, C-04, C-08, NFR-02

## 決定

### 参考文献（成功条件 3 / FR-05）

- **アプリ内ライブラリを第一級の機能として持つ。** 外部マネージャへの保存を本線にしない
- データはローカル（`C-01`）。書誌＋コレクション／タグ。日次候補から追加できる
- UI は一覧＋詳細の参考文献マネージャ形。外部アプリの起動を必要としない
- 保存状態は行が自分で持つ（別のキュー表を作らない）

特定マネージャを前提にすると、その導入有無で成功条件 3 を満たせなくなるため。
他マネージャからの取込・双方向同期は初版の必須にしない（アダプタ／任意機能）。

### `references/` の追従

作業フォルダの `references/` に利用者が公開文献の PDF を置いたら、**ライブラリへの明示追加**とみなす。関連度が高いだけでは入れない。フォルダから引用ファイルへ直書きしない。正本は SQLite のライブラリ行。

1. 置く → ライブラリ行を作る（ローカル抽出。PDF は動かさない）
2. 書誌補完（ADR-0002 C1。Orca 安価モデル）
3. 書き出し先が設定済みなら FR-12

置くことが C1 の明示なので、詳細画面のボタンを待つ必要はない。未公開のノートはこの経路に載せない。

`mypaper/` は読む順の正本（ADR-0001）であると同時に、**自分の論文の置き場**でもある。

- `.md` / `.tex` / `.typ` はローカルだけ。本文を BFF に送らない（C-01）
- **PDF を置いたとき**は `references/` と同じく書誌を作る（C1。1 ページ目の公開書誌）。原本は動かさない（C-08）。ライブラリ行も作る
- 配置はコピー。既存ファイルは上書きしない

### PDF とノート（FR-05, FR-14）

外部ビューアの起動を必要としない。管理から閲覧・注釈までアプリ内で完結させる。

- PDF はローカルに添付して保存し、アプリ内ビューア（**pdf.js**）で開く。
  Electron に同梱済みの実行基盤で足り、ランタイムを増やさない（`NFR-05`）
- **ハイライト・注釈・ノートはローカル DB に持ち、PDF 本体には書き戻さない**（`C-08`）。
  利用者が置いた原本のバイト列を変えない。他ツールで開いても壊れていない
- 利用者が置いた／取り込んだファイルは動かさない。それに加えて、公開メタデータに **PDF の直 URL** があるものだけローカルへ取得する:
  - **採点用**: `{root}/candidates/{paper_id}.pdf`（ライブラリ行は作らない。ADR-0001）
  - **ライブラリ保存後**: `{root}/references/` に寄せる／添付する。候補側にあれば取り直さない
- **直 URL は収集時に一緒に取る。**BFF が OpenAlex の `best_oa_location` / `primary_location` / `locations` / `open_access.oa_url` から https の直 PDF を選び、`run_papers.pdf_url` として同期する。
  **複数あるときは arXiv 等の全文リポジトリを優先する**（購読ページに当たらず、確実に全文が読めるため）。
  1 件ずつ DOI で引き直すのは、収集時に直 URL が取れず、かつ `mypaper` 採点で本文が要るときだけ
- 粗選別が同点のときは**直 PDF がある候補を上に出す**。読めないものを読む順の上位に置かない。粗点の差は PDF の有無で覆さない
- 直 URL が無い、有料、HTML しか無い、取得失敗は **「未取得」** と出す。空ファイルを成功にしない（`C-07`）。PDF が無い候補は**未採点のまま**（要旨で全文のふりをしない）
- 既に添付／候補ファイルがある文献は取り直さない。既存ファイルは上書きしない（`C-08`）
- 取得はデスクトップが行う。BFF は公開の `pdf_url` を返すだけ。PDF バイトはクラウドに置かない
- 注釈・ノートは未公開の思考であり、外部 LLM に送らない（`C-01`, `C-03`）
- 添付 PDF はクラウドに置かない（ADR-0004 で R2 を採らないのはこのため）

### 引用ファイルへの自動書き出し（FR-12）

ライブラリに入れた文献は、**原稿から `\cite{}` できる状態まで自動で持っていく。**
「手で `.bib` に書き写す」を残すと、参考文献マネージャとしての価値が出ない。

- **契機はライブラリへの追加／更新／削除に同期する。** 関連度が高いだけでは書き出さない
  （ユーザーが明示的に入れたものだけが原稿に出る方が予測しやすい）
- 形式はアダプタ。`.bib`（BibTeX/BibLaTeX）と Hayagriva `.yml`（Typst）。
  原稿形式アダプタ（後述）と対応させる
- **既存ファイルに追記する。** 専用ファイルに分離しない（`\bibliography{}` の書き換えを強いない）

#### 他人のファイルを壊さない

書き出し先はユーザーの原稿リポジトリなので、破壊しないことを最優先にする。

- 管理範囲を**マーカーで区切り、マーカー外は読むだけで絶対に書き換えない**
- マーカー行に「触るな」と明記する（例: `% === ai-research:begin (do not edit) ===`）
- 追加・更新・削除はマーカー内の再生成で行う
- **マーカー内に手編集が検知されたら、上書きせず警告して終わる**
- マーカーごと消されていた場合は**何もしない**（勝手に書き戻さない）。
  ユーザーが意図的に外した可能性があり、追跡は諦める
- 書き出し先が未設定なら何もしない。勝手にファイルを作らない

#### key

- `bibtex_key` はプロジェクト内で一意。著者姓＋年で自動生成し、衝突は英字サフィックス
- DOI が一致する項目は既存とみなし、重複エントリを作らない

却下:

- 既存 `.bib` の全体上書き（手で書いた項目が消える）
- 専用ファイルへの分離（ユーザーに `\bibliography{}` の変更を強いる）
- マーカーを消されたケースでの自動復元（意図を無視することになる）
- **`references/` から引用ファイルへ直書きする**（ライブラリを経由しない。正本が割れる）

### CLI（成功条件 7 / FR-11）

- **GUI と同じローカルストアを共有する第二の操作面。** 二重管理しない
- 初版は追加・検索・一覧・（決まれば）書き出し
- Electron 未起動でもライブラリ操作ができること（`NFR-02`）

### 原稿・ファクトチェック（成功条件 4）

- 形式アダプタ: `.md` → `.tex` → `.typ`（優先順）。ローカル監視＋手動投入。監視先の既定は作業フォルダの `mypaper/`（ADR-0001）。Overleaf 専用橋は作らない
- パイプライン: **抽出 LLM（セクション投入・安価モデル固定）→ ローカル RAG → 検証 LLM（主張ごと・高性能固定）**
- C3。auto ルーティング禁止。同意でセクション送信を正確に示す。「主張のみ」と偽らない
- Typst パーサは供給リスクあり → アダプタ疎結合、最悪行ベースへ

却下:

- 特定マネージャ（Zotero 等）を成功条件の本線・必須依存にする
- **PDF 本体に注釈を焼き込む**（利用者の原本を書き換える。`C-08`）
- **添付 PDF をクラウドに置く**（`C-01`。保存先も増える）
- **PDF を外部ビューアに投げる**（「1 アプリで完結」が崩れる）
- **有料 PDF のスクレイプ、影ライブラリ、直 URL が無い HTML からの推定ダウンロード**
- **直 URL が無い候補の PDF を無理に取ること**（未取得・未採点。`C-07`）
- ライブラリをクラウド必須にする
- GUI と CLI で別ストアを持つ
- Overleaf git bridge / 機械抽出のみを本線
