# ADR-0012: 埋め込み空間を設定駆動にする（ADR-0006 を置き換え）

- **ステータス**: 承認済み
- **日付**: 2026-09-19
- **置き換え対象**: ADR-0006

## コンテキスト

ゴールの分野非依存（`C-05` / `FR-06`）に対し、ADR-0006 は specter2 等を決定に埋め込んでいた。
本質は「モデルごとに空間を分け、混ぜたら実行時エラー」なのでそれを残し、モデルは設定へ外出しする。

## 決定

### 1. 空間は「用途」で定義し、モデルは設定で指定する

用途（role）は固定、モデルは設定可能にする。

| role | 格納対象 | 既定モデル | ベクトルの入手 |
|---|---|---|---|
| `papers` | 公開論文 | ソースが配布するものを優先、無ければ設定のモデル | API 取得またはローカル推論 |
| `personal` | 未公開の研究データ・原稿・メモ | `Xenova/multilingual-e5-large` | **ローカル推論のみ**（ADR-0003） |

既定値は「多くの分野で無難に動くもの」を選ぶ。specter2 は
**CS・自然科学分野向けのプリセットとして提供**するが、既定にはしない。

### 2. 空間の識別子は (project, role, model, version) の組

```
space_id = {project_id}/{role}/{model_id}@{model_version}
```

LanceDB のテーブルをこの単位で分ける。ADR-0006 の
「テーブル分離で構造的に異空間比較を防ぐ」を、プロジェクト次元を加えて継承する。

### 3. 異空間比較は実行時エラーにする（ADR-0006 から継承）

これは ADR-0006 の最も価値ある部分なので、そのまま保持する。

- 各レコードに生成元モデルの識別子とバージョンを必ず保存する
- 検索時にクエリベクトルの生成モデルとテーブルのモデルが一致することを検証する。
  **不一致なら実行時エラー**とする
- 次元数が偶然一致する場合も同様にエラーとする

理由も継承する。フィルタ漏れで異空間比較が起きた場合、
**エラーにならず静かに無意味な結果を返すのが最悪の失敗**である。
構造的に防ぐ。

### 4. ソースが配布する埋め込みを優先的に使う

ADR-0009 の `PaperSource.capabilities.embedding` を見て、
ソースが埋め込みを配布していればそれを使う（ローカル推論を省ける）。

Semantic Scholar が specter2 を配布しているのはその一例であり、
**ADR-0006 のように特定ソースに依存する形ではなく、
capabilities 経由で一般化して扱う。**

ソースが埋め込みを配布しない場合、または配布モデルが
プロジェクトの `papers` 空間の設定と異なる場合は、
要約テキストからローカル推論で生成する。

### 5. クロス空間の比較は再埋め込みで橋渡しする（ADR-0006 から継承）

`papers` と `personal` でモデルが異なる場合、ベクトルを直接比較しない。

1. 論文の要約テキストを `personal` 空間のモデルで再埋め込みして検索する
2. またはテキストベースの手法（BM25、キーワード、LLM 判定）を使う

両空間で同一モデルを設定した場合は、この橋渡しは不要になる。
**設定次第で単一空間構成も選べる**ことが、ADR-0006 に対する改善点である。

### 6. モデル変更時の再構築を明示的に扱う

モデルを変更すると該当空間の全再構築が必要になる。

- 設定変更時に「再構築が必要」であることと、推定所要時間を提示する
- 再構築中も旧空間で検索を継続できるよう、新空間を別テーブルとして構築してから切り替える
- `personal` 空間の再構築はローカル推論なので費用はかからないが、時間がかかる

## 検討した代替案

**ADR-0006 をそのまま維持する** — 変更コストが無い。しかし分野非依存
（ADR-0009）とプロジェクト分離が実現できない。却下。

**単一モデルで全用途を統一する** — 空間管理が最も単純で、
クロス空間問題が消える。設定で両 role に同一モデルを指定すれば
**この構成も選べる**ようにしたため、決定として排除する必要がなくなった。
既定にはしない（論文間類似検索で専用モデルの優位を捨てることになる）。

**モデルを完全に自由にする（任意の HuggingFace モデル）** — 柔軟だが、
ONNX 版の有無、次元数、pooling 方式の差異で壊れやすい。
**検証済みモデルの候補リストから選ぶ**方式にし、任意指定は上級設定に留める。

## 帰結

**良い点**

- 分野に応じて埋め込みモデルを選べる。「分野確定待ち」の依存が消える
- プロジェクトごとに異なるモデルを使える（分野を移っても過去の空間が壊れない）
- ソースが配布する埋め込みを一般化して活用できる
- 設定次第で単一空間構成にもできる（管理を単純化したい利用者向け）
- ADR-0006 の異空間比較防止という最も価値ある部分を継承している

**悪い点**

- 空間が「プロジェクト × 用途」の 2 次元になり、管理とマイグレーションが複雑になる
- 設定項目が増え、利用者が選択を誤る余地がある。プリセットの整備が必要
- モデル変更時の再構築フローを実装する必要がある
- 検証済みモデルの候補リストを維持する運用コストが生じる

## ADR-0006 からの変更点まとめ

| | ADR-0006 | ADR-0012 |
|---|---|---|
| モデル指定 | ADR に固定（specter2 / e5） | 設定で指定、プリセット提供 |
| 空間の次元 | 用途のみ | プロジェクト × 用途 |
| Semantic Scholar | 決定に組み込み | `capabilities` 経由で一般化 |
| 異空間比較の防止 | テーブル分離 + 実行時エラー | **同じ（継承）** |
| 単一空間構成 | 不可 | 設定で可能 |
