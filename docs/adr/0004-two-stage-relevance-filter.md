# ADR-0004: 関連度判定を「クラウドで粗く、ローカルで精密に」の二段フィルタにする

- **ステータス**: 承認済み
- **日付**: 2026-09-19

## コンテキスト

成功条件 2: 起動すると重複・活用可能性の報告が読める（`FR-02`）。
ADR-0002（クラウド日次）と ADR-0003（ローカル RAG）の組み合わせでは、
クラウドがローカル RAG を参照できない、という矛盾がある。

テーマ候補（成功条件 6）も、粗い候補集合の上に載せる（ADR-0016）。

## 決定

関連度判定を2段階に分ける。

**第一段 — クラウド（粗いフィルタ）**

クラウドに置くのは **研究プロフィール** のみ（公開可能な範囲）:

- キーワード、公開可能な研究概要、既知論文の識別子、追跡著者・会議

生の実験データ・ノート・書きかけ原稿は置かない（`C-01`）。

cron は再現率優先で緩めに絞り、日次レポートとして D1 へ。

**第二段 — ローカル（精密フィルタ）**

起動後、候補に対しローカル RAG で適合率優先の判定:

- 自分の研究データとの重複
- 書きかけ原稿との照合
- 活用可能性
- テーマ候補生成の入力にもこの集合を使う（ADR-0016）

## 検討した代替案

**全件を D1 へ** — 安全だが同期・計算が重い。却下（分野が十分狭い場合は再検討可）。

**プロフィールに未公開を含める** — `C-01` に反する。却下。

## 帰結

**良い点**: 成功条件 1 と 2、および `C-01` を両立。第一段の取りこぼし件数を可視化できる（`FR-08`）。

**悪い点**: 二段の実装とプロフィールメンテが必要。第一段の閾値調整が要る。
