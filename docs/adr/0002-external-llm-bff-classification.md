# ADR-0002: 外部 LLM・BFF・データ分類

- **ステータス**: 承認済み / **日付**: 2026-09-19（改訂 2026-09-20: 関連度の採点を対象外に／同日: 29行目の陳腐化した「競合／重複はローカル LLM」記述を訂正／改訂 2026-09-21: 書誌補完は Jev。生成 LLM で著者・DOI を埋めない）
- **要件**: FR-10, C-02, C-03, C-04, C-06, C-09, NFR-04

## 決定

外部 LLM 利用自体がプロダクト目的に含まれる（成功条件 5）。

**ただし論文の関連度の採点は対象外。**採点はローカル推論で完結し（`C-09`, ADR-0001）、
BFF に採点用 endpoint を作らない。生成 LLM が担うのは **C1 トレンド要約、テーマ候補（C2）、ファクトチェック（C3）**。
公開書誌の穴埋めは生成しない。OpenAlex で候補を取り、**Jev（System One）で同一論文かを切る**。

```
Electron ──(ユーザー OAuth+PKCE)──→ BFF ──(Workers Secrets)──→ OrcaRouter ──→ 上流
                                              └──────────────→ TypeSafe Jev（判定のみ）
                                              └──────────────→ OpenAlex（公開書誌）
```

- **生成 LLM** は OrcaRouter。キー `cron` / `interactive` / `sensitive`。クライアントに置かない
- **判定**（noul / choice / score）は TypeSafe Jev。Orca に無い。キー `JEV_API_KEY`。クライアントに置かない
- 機能ごと endpoint。自由プロキシ禁止。監査に本文を残さない。経路はコードが決める（`hono-jev-router` は使わない）
- ゲートウェイゼロ保持は自社のみ → 「残らない」と説明しない

| | C1 | C2 | C3 |
|---|---|---|---|
| 用途例 | トレンド（Orca）／**公開書誌の補完**（OpenAlex→Jev） | **テーマ候補**（既定） | ファクトチェック |
| モデル | トレンドは明示 fallback。書誌は `jev-1.13.0` 固定（閾値は `jev-policy.ts`） | 許可リスト | **固定・FB無効** |
| 同意 | 不要 | 初回 | プレビュー必須。範囲を偽らない |
| その他 | 全滅は 502。分類は BFF のコードが決める。Jev 不採用なら項目は null（C-07） | | 機能ごと完全オフ可。`fail_open: false` |

分類は BFF が機能で決める。新機能は分類決定後に endpoint。
**関連度の採点・順位付け（FR-02）はローカル推論のみで完結する**（ADR-0001。生成 LLM は使わない）。手元論文を BFF に載せない。

却下: キー同梱 / ゼロ保持 alone で C3 許可 / **採点 endpoint を BFF に置く**（`C-09`） / **書誌の著者・DOI を生成 LLM（Orca `json_schema`）で埋める** / **HTTP 経路を Jev に決めさせる**（`hono-jev-router`。分類は BFF のコード。Bearer・本文を経路判定で外に出さない）
