# ADR-0004: Cloudflare エッジ防御と日次実行（無料枠前提）

- **ステータス**: 提案 / **日付**: 2026-09-20
- **要件**: FR-01, FR-10, C-02, C-06, NFR-01
- **前提**: [ADR-0001](0001-runtime-local-data-extensibility.md)（二層）、[ADR-0002](0002-external-llm-bff-classification.md)（BFF・分類）

3 本に入れなかった理由: 実行形態（0001）と BFF（0002）の両方に跨り、ゾーン設定という別レイヤのため。

## 決定

**ゾーン・Workers とも Free プランで成立させる。** 有料前提の機能（API Shield・Health Checks）は使わず、同等の目的を Worker 側の実装で満たす。上流 LLM の従量課金（ADR-0002）が主コストであり、基盤で固定費を作らない。

### 公開面は 1 つ

- 公開するのは Cloudflare ゾーン配下の独自ドメイン（例 `api.<domain>`）に載せた Worker のみ
- `workers.dev` は無効化（`workers_dev: false`）。公式に「Free website として扱う／業務利用向けではない」とされるため、防御の前提にしない
- D1 は Worker からのみ。直接の公開面を作らない

### 使うもの・使わないもの

| | 採否 | 理由 |
|---|---|---|
| DDoS 防御 | **使う**（設定不要・無料） | 全プランで常時有効 |
| WAF Free Managed Ruleset | **使う** | 全プランで利用可 |
| WAF カスタムルール | **使う**（5 本以内） | Free は 5 本。正規表現は使えない |
| レート制限ルール | **補助として使う**（1 本） | Free は 1 本・IP 基準・10 秒窓のみ |
| 利用者単位の制限 | **Worker 内で実装** | 上記の制約を補うため |
| JWT 検証・入力検証 | **Worker 内で実装** | API Shield を使わないため |
| Queues | **使う** | Free でも 1 日 1 万操作。CPU 制約の回避に要る（後述） |
| API Shield | **使わない** | Enterprise アドオン（C-02 と釣り合わない） |
| Health Checks | **使わない** | Pro 以上。かつ cron の不発を検知できない |

### 無料枠で効く制約と、その回避

**CPU 時間 10ms／1 実行（HTTP・cron とも）が最大の制約。** 通信の待ち時間は CPU 時間に入らないが、取得結果の解析と採点は入る。

- **1 実行で全部やらない**。cron は Queues に投入するだけにし、実際の収集は 1 メッセージ＝1（プロジェクト × ソース）で処理する
  - 実行を分ければ 10ms 枠がメッセージごとに与えられる
- 粗い採点は**文字列一致の水準に留める**。重い処理はローカルへ（ADR-0001 の精密判定）
- 取得件数を 1 実行あたりで区切り、続きは次のメッセージに回す
- **D1 は 1 実行 50 クエリまで（Free）**。1 件ずつ INSERT せず、複数行を 1 文にまとめる
- **サブリクエストは 1 実行 50 まで（Free）**。ページングは分割して回す

### 防御の層

1. **DDoS**（常時・設定不要）
2. **WAF Free Managed Ruleset** — `log` で開始し、誤検知を潰してから有効化
3. **WAF カスタムルール（5 本まで）** — 知らない経路・メソッドを落とす、過大なリクエストを落とす
   - **正規表現は使えない**ため `starts_with` などの文字列演算子で書く
4. **レート制限（1 本）** — 認証前の入口に限って置く
5. **Worker 内** — JWT 検証 → 入力検証 → 利用者単位の制限 → 処理

- Free のレート制限は IP 基準・10 秒窓のみで、NAT 配下を巻き込む。緩い閾値から始める
- 利用者単位の制限は `auth.user_id` を鍵に Worker 内で数える（置き場所は未決）

### 日次収集は Cron Triggers（FR-01, NFR-01）

- 日次の cron は**投入のみ**。収集は Queues のコンシューマ側
- **UTC のみ**。夏時間の影響を受けない時刻を選ぶ
- **at-least-once**（cron・Queues とも）。冪等にする
  - `runs` の一意キーを `(project_id, run_date)` にし、重複実行は無視する
- 失敗と 0 件は `runs.status` で区別し、ソース単位の失敗は `failed_sources_json` に残す（FR-01）
- **cron トリガーはアカウントで 5 本まで（Free）**。プロジェクトごとに cron を増やす設計にしない
- `__scheduled` は本番で塞ぐ

### 死活監視は自前でやる

- **Health Checks は使わない**。Pro 以上が必要なうえ、**cron の不発を検知できない**（Worker に監視対象の origin が無く、実行漏れは HTTP 応答に現れないため）
- 代わりに **自己点検 cron**: 収集より後の時刻に動かし、D1 を見て当日の `runs` が無いプロジェクトを異常として通知する（cron 2 本目）
- 実行ログは Workers 側の観測機能で見る。**LLM の本文は残さない**（ADR-0002）

### 鍵と構成管理

- 上流 LLM の鍵は Workers Secrets のみ。クライアントに置かない（C-06）
- WAF・レート制限・cron の設定はコードで管理する（wrangler / Terraform）

## 無料枠の実測値（2026-09-20 時点・Cloudflare Docs）

### Workers / D1 / Queues

| 項目 | Free | 有料（$5/月〜） |
|---|---|---|
| リクエスト | 10 万/日 | 1,000 万/月込み |
| **CPU 時間（HTTP）** | **10 ms/実行** | 30 秒（既定） |
| **CPU 時間（cron）** | **10 ms/実行** | 30 秒（間隔 1 時間未満）／15 分（1 時間以上） |
| サブリクエスト | 50/実行 | 1,000〜 |
| cron トリガー | 5/アカウント | 250 |
| D1 読み取り | 500 万行/日 | 250 億行/月込み |
| D1 書き込み | 10 万行/日 | 5,000 万行/月込み |
| D1 容量 | 5 GB（1 DB 500 MB） | 5 GB 込み（1 DB 10 GB） |
| D1 クエリ/実行 | 50 | 1,000 |
| Queues | 1 万操作/日 | 100 万操作/月込み |
| メモリ | 128 MB | 128 MB |

### ゾーン（セキュリティ）

| 項目 | Free | Pro |
|---|---|---|
| DDoS 防御 | 常時有効 | 同じ |
| DDoS 上書き | 1 本（カスタム式・`log` 不可） | 同じ |
| WAF カスタムルール | 5（正規表現 不可） | 20 |
| WAF マネージド | Free Managed Ruleset のみ | Cloudflare Managed 等 |
| レート制限ルール | 1（IP のみ・10 秒窓） | 2（最大 1 分） |
| Health Checks | 不可 | 10 |

**DDoS について**：遮断そのものは Free でも自動で効く。差が出るのは「調整」で、Free は上書き 1 本・カスタム式不可・`log` 不可。

## 有料に移る引き金

次のいずれかが起きたら Workers 有料（$5/月〜）に上げる。先回りして払わない。

- 1 実行の CPU が 10ms を超え、分割でも収まらない
- リクエストが 10 万/日、または D1 書き込みが 10 万行/日に迫る
- cron トリガーが 5 本で足りない
- Queues が 1 万操作/日に迫る

ゾーンの Pro（$20/月〜）は、WAF カスタムルール 5 本で足りなくなるか、正規表現が要るようになってから。

## 却下

- `workers.dev` をそのまま公開面にする（ゾーンの防御が前提にできない）
- API Shield / Health Checks を前提にする（有料プラン前提になり C-02 と釣り合わない）
- cron 1 実行で全プロジェクトを収集する（CPU 10ms に収まらない）
- プロジェクトごとに cron を増やす（Free は 5 本まで）
- レート制限だけで濫用を防ぐ（Free は 1 本・IP のみ・10 秒窓）
- 手動でのゾーン設定運用（再現できない）

## 未決

- 粗い採点をどこまで Worker でやるか（10ms に収まる範囲の見極め）
- 自己点検の通知先
- Workers Custom Domain と Route で WAF 適用に差があるか（公式記述を確認できず。導入時に実機確認）
