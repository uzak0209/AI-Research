## 決定の相互関係

ADR-0002（定期実行をクラウドへ）と ADR-0003（RAG をローカルへ）は直接の緊張関係にあり、
ADR-0004 がその解決策である。この 3 つは一体として読むこと。

ADR-0007（ゲートウェイ）を導入すると、未公開データがプロンプトとして外部を通過する。
これは ADR-0003 と衝突しうるため、ADR-0010 がデータ分類で解決している。
**ADR-0003・0007・0008・0010 も一体として読むこと。**

```
ADR-0002 クラウド cron ──┐
                          ├─→ 矛盾 ─→ ADR-0004 二段フィルタで解決
ADR-0003 ローカル RAG ───┘

ADR-0003 ローカル埋め込み ─→ ADR-0005 Node で実現可能

ADR-0007 ゲートウェイ ──┐
                         ├─→ 緊張 ─→ ADR-0010 データ分類で解決
ADR-0003 未公開データ ──┘         └─→ ADR-0008 BFF が統制を執行

ADR-0009 分野非依存 ─→ ADR-0012 が ADR-0006 を置き換え
ADR-0007 外部依存の増加 ─→ ADR-0011 縮退設計
```

## 貫かれている原則

**1. 未公開データの恒久的なインデックスを外部に作らない。**
埋め込みはローカル推論のみ（ADR-0003, ADR-0012）。
クラウドに置くのは公開可能な研究概要・キーワード・論文識別子のみ（ADR-0004）。

**2. LLM 推論は分類に応じた統制の下でのみ外部へ出す。**
埋め込み（全件・恒久）とプロンプト（都度・必要範囲）はリスクの性質が異なるため
扱いを分ける。この非対称性は意図的であり、ADR-0003 の適用範囲節と ADR-0010 に根拠がある。

**3. 秘匿性が可用性より優先される場面がある。**
C3（機密）ではフォールバックを無効化する（ADR-0010）。
通常は可用性を優先する（ADR-0011）が、未公開原稿の転送先が
予測できなくなることは許容しない。

**4. 無言で失敗しない。**
欠損を成功と区別し、必ず気付ける形で提示する（ADR-0011）。

**5. 分野固有の知識をコードに埋め込まない。**
設定とアダプタに外出しする（ADR-0009, ADR-0012）。

## 新しい ADR を追加する

1. 連番の次の番号を使い、`NNNN-kebab-case-title.md` で作成する
2. コンテキスト / 決定 / 検討した代替案 / 帰結 を書く
3. この README の一覧に追記する
4. ルート `README.md` の ADR 表にも追記する
5. 既存の決定を覆す場合は、旧 ADR を書き換えず、
   ステータスを `置き換え済み (ADR-XXXX による)` に変更する

**新機能を追加するときは、必ず ADR-0010 のデータ分類を決めてからエンドポイントを作る。**
